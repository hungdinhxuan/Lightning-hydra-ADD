````markdown
# Benchmark Baseline Model under Different Short-duration Inference Modes

## 1. Objective

The goal of this evaluation is to benchmark the current baseline MDT model on short-duration evaluation data.

The evaluation datasets have already been pre-processed:

- Observed-short
- VAD-short

No additional fixed-window dataset will be generated.

Fixed-window behavior will only be applied at inference time by reusing the existing benchmark codebase.

Main questions:

1. How does the current MDT baseline perform on Observed-short and VAD-short data?
2. How does performance change with different fixed-duration inference windows?
3. Which inference duration works best for short speech segments?
4. Does multi fixed-duration inference improve robustness compared to single-duration inference?
5. Which dataset, duration bin, or label type causes the largest degradation?
````

````markdown
## 13. Multi-GPU Evaluation Notes

The evaluation server has multiple GPUs, so the benchmark should try to utilize all available GPUs as much as possible.

### Recommended strategy

Run independent benchmark jobs in parallel across GPUs.

Since different inference durations are independent, assign each duration or dataset split to a different GPU.

Example:

```bash
# GPU 0: VAD-short, 0.5s
CUDA_VISIBLE_DEVICES=0 DEFAULT_BATCH_SIZE=128 OMP_NUM_THREADS=8 uv run ./scripts/benchmark_py/benchmark.py \
  -g 0 \
  -c xlsr_conformertcm_normal \
  -b data/vad_short_test \
  -m /NAS1_pretrained_lab/May_21_2026_TCM_MDT.pt \
  -r logs/results/baseline_mdt_short_eval \
  -n "baseline_mdt_vad_short_0.5s" \
  -l false \
  +trainer.precision=bf16-mixed

# GPU 1: VAD-short, 1.0s
CUDA_VISIBLE_DEVICES=1 DEFAULT_BATCH_SIZE=128 OMP_NUM_THREADS=8 uv run ./scripts/benchmark_py/benchmark.py \
  -g 0 \
  -c xlsr_conformertcm_normal \
  -b data/vad_short_test \
  -m /NAS1_pretrained_lab/May_21_2026_TCM_MDT.pt \
````

### Important notes

* Use `CUDA_VISIBLE_DEVICES=<gpu_id>` to isolate each benchmark process.
* Keep `-g 0` inside the command when each process only sees one GPU through `CUDA_VISIBLE_DEVICES`.
* Split jobs by:

  * dataset type: `Observed-short` / `VAD-short`
  * subset: `dev` / `test`
  * inference duration: `0.5s / 1.0s / 1.5s / 2.0s`
  * model checkpoint
* Avoid writing multiple jobs to the same score filename.
* Make sure every job has a unique run name via `-n`.
* Make sure every job writes to a unique output directory or unique score file.
* Monitor GPU utilization with:

```bash
watch -n 1 nvidia-smi
```

### Suggested job scheduling

For a multi-GPU server, the preferred execution order is:

```text
1. Run sanity jobs first on a small subset.
2. If score files look correct, launch all single-duration jobs in parallel.
3. Use all GPUs by distributing duration/dataset combinations across devices.
4. Run multi-duration inference jobs after single-duration outputs are verified.
5. Run metric/report generation after all score files are complete.
```

```text
Observed-short dev  × 0.5s
Observed-short dev  × 1.0s

Observed-short dev  × 2.0s

Observed-short test × 0.5s

Observed-short test × 1.5s
Observed-short test × 2.0s

VAD-short dev       × 0.5s
VAD-short dev       × 1.0s

VAD-short test      × 1.0s

```

Each row can be treated as an independent job and assigned to an available GPU.

### Batch size tuning

Start with:

```bash
DEFAULT_BATCH_SIZE=128
```

If GPU memory is underused, increase gradually:

```bash
DEFAULT_BATCH_SIZE=192
DEFAULT_BATCH_SIZE=256
```

If out-of-memory occurs, reduce:

```bash
DEFAULT_BATCH_SIZE=64
```

Keep CPU workers and thread settings controlled to avoid CPU bottlenecks:

```bash
OMP_NUM_THREADS=8
```

For many parallel jobs, reduce per-job CPU threads if needed:

```bash
OMP_NUM_THREADS=4
```

### Expected outcome

The evaluation should maximize GPU utilization by running independent fixed-duration inference jobs in parallel, while keeping output files isolated and reproducible.
